# 現代的な日本語・長音符と段別運動モデルの感度試験

2026-10-31。モデル基準コミット: `111f20d6408e334f6a691adf7aed4316368b81ab`。既存9配列は固定し、再最適化していない。KLA型近似値であり、Patorjk公式サイトで直接実行した結果でも、実測WPMでもない。

## 1. 元の日本語ベンチマークの訂正

保存された日本語ベンチマークは、青空文庫ではなく、自作の6課題（2,749ローマ字打鍵）である。青空文庫を用いた外部の文字頻度統計の紹介と、実際にベンチマークに使用した文章を区別する必要がある。元データは [`data/jp_en_corpora.json`](../data/jp_en_corpora.json)。元の6課題にはアプリ開発なども含むが、長音符は合計10回、全打鍵の0.3638%だけである。

## 2. 今回の入力

買い物、連絡、業務、開発、研究、ゲームをテーマとする自作6課題を追加した。**外来語を意図的に多くした現代文風の感度試験であり、現代日本語全体の無作為標本ではない。** BCCWJや実ニュースの測定結果ではない。

原文・読み・固定したローマ字列: [`data/modern_jp_corpora.json`](../data/modern_jp_corpora.json)。`ー`は必ず`-`として保持し、長母音への置換・削除をしない。旧課題と同じ`si/ti/tu/hu/zi`などの綴り方を用い、外来語の小書きかなには`thi/fi/fo/tye/je`などを用いた。IME変換・候補選択の操作は除外している。

### 長音符の位置だけでなく、母音との指の競合が重要

今回、長音符の直前の母音は `a:45 / e:25 / o:18 / i:16 / u:14`。5母音で118回すべてを占める。

| 配列 | 長音符の位置 | 同じ指にある母音 | 今回の長音符を含む異鍵同指遷移 |
|:--|:--|:--|--:|
| 大西 | 中段・左人差し指の内側 | o | 18 |
| Nova-JP | 上段・左中指 | e, o | 43 |
| Nova-Hybrid | 下段・左中指 | a, u | 59 |
| Nova-Dev | 上段・左中指 | i | 16 |
| Nova-Ctrl | 上段・左人差し指の内側 | a, u | 59 |

この差は長音符増加の影響を示す一要因である。ただし文章変更により他の文字・遷移頻度も変わっており、表全体の差をすべて長音符だけの因果効果とは解釈できない。

### 文章集合の混合感度

文字列を連結せず、文書内のユニグラム・バイグラムを打鍵数で正規化して混合した。文書の境界に架空の遷移を作っていない。

| 今回の課題の重み（打鍵数比） | 長音符の割合 | 大西KLA型 | Nova-JP KLA型 |
|--:|--:|--:|--:|
| 0% | 0.36% | 76.12 | 76.59 |
| 25% | 1.35% | 75.52 | 75.52 |
| 50% | 2.34% | 74.75 | 74.45 |
| 75% | 3.33% | 73.98 | 73.03 |
| 100% | 4.32% | 73.22 | 71.23 |

25%の値は小数2桁で同値。これは特定の2文章集合の混合であり、「長音符1.35%が普遍的な逆転閾値」という意味ではない。

## 4. 現在の中段・上段・下段モデル

実装は [`src/benchmark.py`](../src/benchmark.py)。キー間隔を1とすると、文字キーの中心座標は上段`(c,1)`、中段`(c+0.22,0)`、下段`(c+0.47,-1)`。8本の指のホームキーからユークリッド距離を測る。

典型的なホームキーと同じ列のキーでは次のようになる（人差し指の内側列は別）。

| 位置 | ホームからの距離 | 往復の距離項 `(19+9)*d` |
|:--|--:|--:|
| 自分のホームキー | 0 | 0 ms |
| 1段上の同列キー | 1.02391 | 28.67 ms |
| 1段下の同列キー | 1.03078 | 28.86 ms |

距離差は約0.67%。**現状は上段と下段をほぼ同じコストとして扱っている。** 中段であっても人差し指の内側キーはホームから1キー分横に離れているので、無料ではない。「ホーム段使用率」と「ホームキー8個の使用率」も別である。

打鍵時間モデルは1打鍵118 msを基本に、異なる指の遷移なら `19*d_next_home + 9*d_prev_home` ms（同手でさらに8 ms）、同じ指の異鍵遷移なら `36 + 56*log2(1+d_pair) + 6*d_pair` msを加える。前者の距離はホーム基準、後者は前後のキー間距離である。

上下方向、指ごとの曲げ伸ばし、キー自体の押しやすさに対する独立した時間係数はない。KLA型にも独立した段別係数はない（距離・指使用分布・連続打鍵に間接的に反映するだけ）。指使用分布のKLA型評価はあるが、時間モデルの118 msは全指で同じである。

### 下段の追加コストを仮定するとどうなるか

今回の現代文6課題に対し、**下段の1打鍵ごとに追加20 ms**、上段・中段は追加0 msと仮定した感度試験。実測値でも推奨係数でもない。既存の距離項は残したままであり、KLA型スコアは変更していない。

| 配列 | 現モデルでの速度増加 | 下段+20 ms仮定での速度増加 |
|:--|--:|--:|
| 大西 | +13.69% | **+14.32%** |
| Nova-Ctrl | +13.15% | +14.09% |
| Nova-JP | **+14.81%** | +13.97% |
| Nova-Dev | +13.51% | +13.96% |
| Nova-Hybrid | +13.65% | +13.36% |

各列は、その列と同じ条件のQWERTYに対する速度増加率。QWERTY自身にも段別追加コストが掛かる。現代文ではNova-JPの下段率17.12%、大西8.53%、Nova-Ctrl6.70%なので、この仮定で順位が変わり得る。これは係数を実測で校正する必要性を示すもので、下段20 msという値が正しい証拠ではない。

## 5. 次のモデルの設計方針

単純な「中段 < 上段 < 下段」の全指共通序列ではなく、指×段×内外側のキー固有コストと、方向非対称の遷移コストを分ける。Workman作者も、長い指の上方向への到達と短い指の屈曲を区別する設計原則を述べている。ただしこれは設計者の仮説であって、実測の普遍定数ではない。

現代文の代表性を評価するには、生活・仕事・開発・研究・メディアなどの独立した実文章を収集し、分野ごとの成績を分けて検証する。BCCWJは候補となるが、年代とジャンル構成を確認する必要がある。長音符は正規化で消さず、原文、読み、実際の入力綴りを保存する。個人のメール・チャットを使う場合は権限確認と匿名化が必要で、公開リポジトリには原文を入れない。

## 再現

```bash
python src/benchmark_modern_jp.py
```

出力: `results/modern_jp/summary.csv`, `by_document.csv`, `mixture_sensitivity.csv`, `row_sensitivity.csv`。元の日本語9配列の時間・KLA型・距離・速度差を既存CSVと許容差0.015で照合する。入力長と原文・読み・ローマ字列の長音符数も検査する。

今回の計算では、添付済みベンチマークから取り出した同式の計算エンジンで元の9配列の結果との一致を確認し、新規感度試験を実行した。公開スクリプトはこのリポジトリの既存`benchmark.py`を直接利用する。既存の集計値・HTMLレポート・配列定義は上書きしていない。
